# Botched renders

This directory preserves rendering mistakes as historical artifacts.

Do not use these files as visual acceptance or as examples of the current
canonical rendering path.  They are kept because generating them cost real
compute and, more importantly, because deleting mistakes makes it easier to
repeat them.

The files here are exact Git blobs copied from the pre-refactor
`rendered_images/` outputs.  They are deliberately preserved before those
canonical paths are regenerated through the shared C/GLES renderer.

## Archived files

### Rational-function movies

- `two_moving_simple_poles.mp4`
- `three_moving_simple_roots.mp4`
- `moving_simple_and_repeated_roots.mp4`
- `moving_simple_and_double_poles.mp4`
- `moving_two_simple_zeros_and_two_simple_poles.mp4`
- `moving_repeated_zeros_and_poles.mp4`

These six movies were generated by a Python/NumPy/Pillow rendering path that
independently evaluated the rational function and independently reimplemented
the Wegert colour rule.  Some frames may be visually close to the intended
result.  That does not make the rendering path acceptable: they did not prove
that Wegert itself, the GLES renderer, or the shader backend produced those
pixels.

### Meromorphic movie

- `wegert_meromorphic_15s.mp4`

This is a stronger failure.  In addition to being rendered independently in
Python, it used a separate `dark_rgb()` HSV/ring colouring rule and an
`exp(0.18 z)` factor outside the current rational `wegert_scene` contract.
It is not a canonical Wegert render.

## Not botched

The preserved R codomain-phase reference
`rendered_images/wegert_g_codomain_phase.mp4` is intentionally a historical
reference renderer with its own documented R rule.  It is not claimed as GLES,
PowerVR, Mali, or shader-backend evidence.

The Android touch recordings are recordings of the running app.  They are also
not part of this archive.

See [JOURNAL.md](JOURNAL.md) for the postmortem and the changes made to prevent
these failures from recurring.
